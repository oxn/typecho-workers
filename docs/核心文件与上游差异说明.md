### 6. `src/lib/markdown.ts`

**差异类型：** 修改  
**上游文件：** `Tokinx/typecho-workers:master/src/lib/markdown.ts`（基准提交 `6f268808f4f510852887f18cf43fd88567d69e15`，413 行）  
**当前文件：** `oxn/typecho-workers:m/src/lib/markdown.ts`（本节更新时提交 `db9f56872220b062e5c31d50fef5ef1015c62527`，544 行）

> 本节已按当前 `m` 分支重新核对。本文开头的整体差异统计及其他核心文件条目仍沿用原先记录的 `24` 分支比较快照，不代表它们已在本次一并重新比对。

**增加内容一：扩展正文 HTML 标签白名单**

在原有 Markdown 正文允许标签的基础上，增加多类 HTML 标签：

- 语义和布局标签：`div`、`span`、`section`、`article`、`main`、`header`、`footer`、`nav`、`aside`。
- 文本标签：`small`、`u`、`mark`、`abbr`、`sub`、`sup`、`time`。
- 列表扩展：`dl`、`dt`、`dd`、`tfoot`。
- 表单标签：`form`、`fieldset`、`legend`、`input`、`select`、`option`、`textarea`、`output`、`progress`、`meter`、`button`、`label`。
- 图片容器：`picture`。
- SVG 标签：`svg`、`g`、`path`、`circle`、`rect`、`line`、`polyline`、`polygon`、`ellipse`、`text`、`tspan`、`defs`、`use`、`symbol`、`mask`、`clipPath`、`filter`、渐变、滤镜及相关子标签。

**增加内容二：扩展 HTML 属性白名单**

- 增加通用属性白名单：`class`、`id`、`title`、`style`、`role`、`aria-*`、`data-*`。
- 链接增加 `download`。
- iframe 增加 `allow`、`sandbox`、`loading`、`referrerpolicy`。
- video 增加 `poster`。
- source 增加 `srcset`、`sizes`、`media`。
- 为表单控件、picture 和 SVG 元素分别增加对应属性白名单。

**增加内容三：增加样式属性过滤配置**

新增 `allowedStyles`，为正文 HTML 的内联样式增加属性和值的过滤规则。配置覆盖颜色、填充、描边、透明度、背景、字体、文本排版、布局、尺寸、间距、边框、阴影、溢出和图片对象适配等样式属性。

相关规则会拒绝包含 `url(...)`、`expression(...)`、`javascript:`、`@import`、`behavior:`、`-moz-binding` 等危险内容的样式值；SVG 的填充、描边和透明度也有单独的值格式限制。

**增加内容四：保留 SVG 标签大小写**

增加：

```ts
parser: { lowerCaseTags: false }
```

用于避免 SVG 中需要区分大小写的标签名称在解析时被统一转换大小写。

**增加内容五：图片尺寸提取，同时保留完整图片 URL**

当前分支增加了 `transformTags.img` 处理：

- 从图片 `src` 中识别 `width`、`height` 参数。
- 仅接受 1 至 16384 范围内的尺寸值，并将有效值写入 img 的 `width`、`height` HTML 属性。
- **保留原始 `src`，不截断 `#` 后的 fragment，也不删除 URL 中的查询参数。** 因此 `#blurhash=...`、`width`、`height` 等数据仍完整留在图片地址中。
- 这项行为在提交 `db9f56872220b062e5c31d50fef5ef1015c62527` 中调整：此前会截断 fragment 或清理尺寸参数；现在改为完整保留 URL，供 Markdown Rehype OXN 插件继续读取和处理。

**增加内容六：扩展 iframe 主机白名单**

在上游原有 YouTube、Bilibili 播放器和 Vimeo 主机基础上，增加：

```ts
www.bilibili.com
```

**删除或替换内容**

- 原来 `a` 标签的属性白名单不包含 `download`，当前增加了该属性。
- 原来 iframe、video、source 的属性白名单较少，当前扩展了上述属性。
- 原来只允许 `www.youtube.com`、`player.bilibili.com`、`player.vimeo.com` 作为 iframe 主机，当前增加 `www.bilibili.com`。
- 上游没有上述扩展标签、SVG 属性和样式过滤配置；当前增加了这些白名单与过滤能力。
- 上游没有 `transformTags.img` 图片尺寸转换逻辑；当前分支增加尺寸提取，但现在保留完整图片 URL，不再清理参数。
- 没有删除 Markdown 主体渲染、GitHub Alerts 转换、评论 Markdown 渲染、过滤器 Hook 或缓存等原有处理入口。

**作用与影响**

当前分支允许文章正文保留更多结构化 HTML、表单和 SVG 内容，同时通过属性白名单、样式过滤和 iframe 主机限制控制输出范围。图片尺寸可以从 URL 参数转换为 HTML 属性，同时原始图片地址完整保留，使后续插件仍能读取 URL fragment 中的 BlurHash 数据。

注意：正文的 `SANITIZE_OPTIONS` 与评论专用的 `COMMENT_MARKDOWN_OPTIONS` 是不同配置，不能把正文白名单扩展理解为评论内容也自动获得同等 HTML 能力。

## 四、阅读和维护注意事项

1. **先看源码，再看主题和插件。** 本文只说明核心层相对上游的变化，不代表主题或插件内部没有差异。
2. **配置文件与锁文件要一起看。** 尤其是 `package.json` 与 `bun.lock`，依赖声明和锁定结果必须保持一致。
3. **Markdown 清理器与 CSP 是两道不同的限制。** iframe 主机既要被正文清理器允许，也要被浏览器 CSP 允许。
4. **日志默认关闭是配置默认值变化。** 不代表日志功能被删除；部署者仍可按实际需要开启。
5. **本文记录的是指定提交之间的差异。** 如果分支或上游 master 后续继续变化，需要重新比对，不能把本文当作永久不变的差异清单。
