# 第二章：`src/lib/image-transform.ts` —— 图片尺寸自动补全

对比文件：

- CY：`src/lib/image-transform.ts`
- 原版：`src/lib/image-transform.ts`

## 一、原版代码

原版的 `optimizeContentImages()` 只负责图片 URL 优化：

```ts
export function optimizeContentImages(html: string, params: string, siteUrl: string): string {
  if (!html) return html;

  const clean = normalizeOptimizeParams(params);
  if (!clean) return html;

  return html.replace(
    /(<img\b[^>]*?\ssrc\s*=\s*)(["'])(.*?)\2/gi,
    (match: string, prefix: string, quote: string, src: string) => {
      const optimized = optimizeImageUrl(src, clean, siteUrl);
      return optimized === src ? match : `${prefix}${quote}${optimized}${quote}`;
    },
  );
}
```

原版有一个限制：

```ts
if (!clean) return html;
```

没有配置图片优化参数时，直接返回 HTML，不会继续处理图片标签。

## 二、CY 删除和修改的代码

### 1. 删除原来的提前返回判断

```diff
- if (!clean) return html;
```

原版在没有图片优化参数时直接结束。

CY 删除这一行，使图片尺寸补全逻辑即使在没有配置图片优化参数时也可以执行。

### 2. 删除原来的单一 URL 替换结构

```diff
- return html.replace(
-   /(<img\b[^>]*?\ssrc\s*=\s*)(["'])(.*?)\2/gi,
-   (match: string, prefix: string, quote: string, src: string) => {
-     const optimized = optimizeImageUrl(src, clean, siteUrl);
-     return optimized === src ? match : `${prefix}${quote}${optimized}${quote}`;
-   },
- );
```

CY 改为逐个匹配 `<img>` 标签，在同一个处理流程中完成尺寸补全和 URL 优化。

## 三、CY 新增的代码

### 1. HTML 为空时提前返回

```ts
if (!html) return html;
```

保留原有空内容判断。

### 2. 新增图片标签扫描

```ts
return html.replace(/<img\b[^>]*>/gi, (tag: string) => {
```

逐个扫描 HTML 中的图片标签，不再只围绕 `src` 属性进行替换。

### 3. 新增读取图片 URL 的代码

```ts
const srcMatch = tag.match(/(\ssrc\s*=\s*)(["'])(.*?)\2/i);
if (!srcMatch) return tag;

const src = srcMatch[3];
```

提取图片的 `src`，没有 `src` 的标签保持原样。

### 4. 新增从 URL 片段中读取宽高

```ts
const fragment = (src.split('#', 2)[1] || '').replace(/&amp;/gi, '&');
```

从 `#` 后面的参数中读取尺寸，并兼容 HTML 转义的 `&amp;`。

新增尺寸解析函数：

```ts
const getDimension = (name: 'width' | 'height'): string | null => {
  const result = fragment.match(
    new RegExp(`(?:^|[&;])${name}=(\\d+)(?=[&;]|$)`, 'i'),
  );

  if (!result) return null;

  const value = Number(result[1]);

  return Number.isInteger(value) && value > 0 && value <= 10000
    ? String(value)
    : null;
};
```

具体规则：

- 支持读取 `width`。
- 支持读取 `height`。
- 参数分隔符支持 `&` 和 `;`。
- 只接受正整数。
- 尺寸范围为 1～10000。
- 不符合规则的值不添加。

### 5. 新增补充图片属性

```ts
let updated = tag;
let attributes = '';

for (const name of ['width', 'height'] as const) {
  const dimension = getDimension(name);
  const hasAttribute = new RegExp(`\\s${name}\\s*=`, 'i').test(updated);

  if (dimension && !hasAttribute) {
    attributes += ` ${name}="${dimension}"`;
  }
}
```

这里最重要的是：

```ts
if (dimension && !hasAttribute)
```

只有图片原本没有对应属性时才补充，不覆盖文章中已经填写的 `width` 和 `height`。

### 6. 新增将属性写回 img 标签

```ts
if (attributes) {
  updated = updated.replace(/\/?>$/, (ending: string) => {
    return `${attributes}${ending}`;
  });
}
```

把补充的尺寸属性放到图片标签结束符之前。

### 7. 保留原来的图片 URL 优化逻辑

```ts
if (clean) {
  const optimized = optimizeImageUrl(src, clean, siteUrl);

  if (optimized !== src) {
    updated = updated.replace(
      /(\ssrc\s*=\s*)(["'])(.*?)\2/i,
      (_match: string, prefix: string, quote: string) =>
        `${prefix}${quote}${optimized}${quote}`,
    );
  }
}
```

这一部分仍然调用原有的 `optimizeImageUrl()`。

也就是说，原来的本站图片 URL 优化功能没有被删除，只是从原来的单独替换流程，调整成了尺寸补全之后继续执行。

最后：

```ts
return updated;
```

返回处理后的图片标签。

## 四、最终执行顺序

CY 版本的 `optimizeContentImages()` 实际执行顺序：

1. 检查 HTML 是否为空。
2. 清理图片优化参数。
3. 扫描所有 `<img>` 标签。
4. 读取图片 `src`。
5. 读取 URL `#` 后面的宽高参数。
6. 判断图片是否已经有 `width`、`height`。
7. 只补充缺失的尺寸属性。
8. 如果配置了图片优化参数，继续优化图片 URL。
9. 返回处理后的 HTML。

## 五、修改前后对比

| 对比项目 | 原版 | CY |
|---|---|---|
| 扫描 img 标签 | 有条件执行 | HTML 非空即执行 |
| 读取 URL 尺寸 | 没有 | 新增 |
| 自动补充 width | 没有 | 有 |
| 自动补充 height | 没有 | 有 |
| 覆盖已有尺寸 | 不涉及 | 不覆盖 |
| 图片 URL 优化 | 有 | 保留 |
| 原始文章内容存储 | 不修改 | 不修改 |

**本章结论：**

CY 对 `optimizeContentImages()` 进行了重构，新增图片尺寸自动补全功能，同时保留原版图片 URL 优化功能。

这项修改属于页面渲染阶段的 HTML 处理，不是重新上传、下载或转换图片，也没有新增 KV、D1、R2 存储操作。



# 第三章：主项目 `src/lib/markdown-alerts.ts` Markdown 提示框处理

**对比对象：** `oxn/typecho-workers` 与 `Tokinx/typecho-workers`

## 1. 本次修改概况

原版已经具备 GitHub 风格 Markdown Alert 的基本转换功能。

CY 版本主要增加了两项改进：

1. 改进多个引用块连续出现时的内容分段处理，避免提示框前后的普通引用内容被错误拆分。
2. 为五种提示框增加对应的 SVG 图标，并在标题区域显示图标。

## 2. 具体增加和修改的代码

### 修改一：改进连续引用块的处理逻辑

**原版代码：**

```ts
const segments: Segment[] = [];
let cursor = 0;

for (const para of paragraphs) {
  const index = cleaned.indexOf(para, cursor);
  if (index === -1) continue;
  const before = cleaned.slice(cursor, index).trim();
  if (before) pushQuote(segments, before);
  cursor = index + para.length;

  const match = para.match(alertParaRe);
  if (match) {
    const label = match[1].trim();
    if (label) {
      const body = match[2].trim();
      segments.push({
        kind: 'alert',
        label,
        body: body ? `<p>${body}</p>` : ''
      });
      continue;
    }
  }
  pushQuote(segments, para);
}
```

**CY 版本增加的代码：**

```ts
let activeAlert: AlertSegment | null = null;
```

并增加了对当前提示框的持续跟踪：

```ts
if (before.trim()) {
  if (activeAlert) {
    activeAlert.body += before;
  } else {
    pushQuote(segments, before.trim());
  }
}
```

普通段落也增加了判断：

```ts
if (activeAlert) {
  activeAlert.body += before + para;
} else {
  if (before.trim()) pushQuote(segments, before.trim());
  pushQuote(segments, para);
}
```

最后一段内容也会继续合并到当前提示框：

```ts
const after = cleaned.slice(cursor);
if (after.trim()) {
  if (activeAlert) {
    activeAlert.body += after;
  } else {
    pushQuote(segments, after.trim());
  }
}
```

**实际效果：**

- 普通引用和提示框可以连续出现。
- 提示框后面的普通段落可以继续归入当前提示框。
- 不同提示框可以分别处理。
- 减少 HyperDown 将连续引用块合并后造成的内容错位问题。

### 修改二：增加五种 SVG 图标

CY 版本新增：

```ts
function alertIcon(label: string): string {
  const icons: Record<string, string> = {
    note: '...',
    tip: '...',
    important: '...',
    warning: '...',
    caution: '...',
  };

  const key = label.trim().toLowerCase();
  const paths = icons[key] || icons.note;

  return `<svg class="markdown-alert-icon"
    viewBox="0 0 16 16"
    width="16"
    height="16"
    fill="currentColor"
    aria-hidden="true">${paths}</svg>`;
}
```

这里的 `...` 代表实际文件中对应的 SVG path 数据，五种图标均已写入 CY 源文件。

| 提示类型 | 图标 |
|---|---|
| NOTE | 信息圆圈 |
| TIP | 灯泡 |
| IMPORTANT | 消息气泡 |
| WARNING | 三角形警告 |
| CAUTION | 八边形警告 |

### 修改三：调整提示框标题输出

**原版删除的标题输出：**

```ts
`<p class="markdown-alert-title">${safeLabel}</p>`
```

**CY 版本替换为：**

```ts
const icon = alertIcon(label);

`<p class="markdown-alert-title">${icon}<span>${safeLabel}</span></p>`
```

最终提示框仍然使用原有结构：

```html

  <p class="markdown-alert-title">
    SVG图标
    <span>NOTE</span>
  </p>
  <p>提示框正文</p>
</blockquote>
```

## 3. 没有修改的部分

# 第四章：主项目 `src/lib/markdown.ts` Markdown 渲染修改

**对比对象：** `oxn/typecho-workers` 与 `Tokinx/typecho-workers`

## 1. 本次修改概况

CY 版本主要有两类修改：

1. 扩展 `sanitize-html` 白名单，支持更多 HTML 标签、属性、SVG 图标和受限的内联 CSS。
2. 四处 Markdown 解析统一增加 `breaks: true`，让普通文本中的单个换行也转换成 HTML 换行。

实际文件还增加了以下属性的校验规则：

**实际效果：**

注意：这不是允许任意 CSS，具体属性和值仍受到白名单限制。

### 修改五：开启 Markdown 单换行转换

这是本次另一项明确的功能修改。

原版：

```ts

```

CY 版本：

```ts

  async: false,
  breaks: true,

```

这个修改在四处解析入口中都进行了调整：

| 位置 | 修改 |
|---|---|
| `renderContent()` | 增加 `breaks: true` |
| `renderCommentText()` | Markdown 评论增加 `breaks: true` |
| `renderMarkdownFiltered()` | 正文插件渲染增加 `breaks: true` |
| `renderContentExcerpt()` | 文章摘要渲染增加 `breaks: true` |

**实际效果：**

原始 Markdown：

```md

第二行文字
第三行文字
```

原版默认不一定将单换行转换为 HTML 换行。

CY 版本开启 `breaks: true` 后，单换行会转换为 `<br>`，阅读时能够保留作者输入的换行效果。

```ts
export function parsePinnedIds(value: unknown): number[] {
  if (typeof value !== 'string' && typeof value !== 'number') return [];

  const parts = String(value).split(/[，,\s]+/);
  const result: number[] = [];
  const seen = new Set<number>();

  for (const part of parts) {
    if (!/^\d+$/.test(part.trim())) continue;

    const cid = Number(part.trim());

    if (!Number.isSafeInteger(cid) || cid <= 0 || seen.has(cid)) continue;

    seen.add(cid);
    result.push(cid);
  }

  return result;
}
```

实际作用：

- 支持英文逗号分隔。
- 支持中文逗号分隔。
- 支持空格分隔。
- 自动过滤非数字、零、负数和不安全整数。
- 自动去重。
- 保留填写顺序。

## 三、新增置顶文章数据库查询

CY 新增：

```ts
if (pinnedIds.length > 0) {
  const pinDb = getDb(env.DB);
  const now = Math.floor(Date.now() / 1000);

  const pinnedRows = await pinDb.select({
    cid: schema.contents.cid,
    title: schema.contents.title,
    slug: schema.contents.slug,
    created: schema.contents.created,
    text: schema.contents.text,
    type: schema.contents.type,
    status: schema.contents.status,
  }).from(schema.contents).where(and(
    inArray(schema.contents.cid, pinnedIds),
    eq(schema.contents.type, 'post'),
    eq(schema.contents.status, 'publish'),
    lte(schema.contents.created, now),
  ));
}
```

查询条件有四项：

| 条件 | 作用 |
|---|---|
| `cid` 在置顶 ID 中 | 只查询后台指定的文章 |
| `type = post` | 只允许普通文章 |
| `status = publish` | 只显示已发布文章 |
| `created <= now` | 不显示尚未到发布时间的文章 |

因此，草稿、页面和未来发布的文章不会进入置顶列表。

## 四、按照后台填写顺序排列

CY 新增：

```ts
const rowById = new Map(

const validIds = pinnedIds.filter(
```

最终生成置顶文章时：

```ts
pinnedItems = validIds.map(cid => {

```

这里使用 `validIds.map()`，所以最终顺序遵循后台填写的 ID 顺序，而不是数据库返回顺序。

同时，CY 还额外查询这些置顶文章的分类信息，保证置顶文章卡片能够正常显示分类。

## 五、防止置顶文章重复出现

这是本次修改中非常重要的一段：

```ts
items = items.filter(
  item =>
    item.type !== 'post' ||
    !pinnedIdSet.has(Number(item.cid))
```

作用：

- 从普通文章列表中排除置顶文章。

- 后续分页也不会再次显示已经置顶的文章。

然后只在首页第一页插入置顶文章：

```ts
if (

  currentPage === 1 &&
  pinnedItems.length > 0
```

最终效果是：

1. 置顶文章出现在首页列表最前面。
2. 置顶顺序按照后台填写顺序排列。
3. 普通文章继续按照原有列表逻辑显示。
4. 置顶文章不会在普通列表中重复出现。
