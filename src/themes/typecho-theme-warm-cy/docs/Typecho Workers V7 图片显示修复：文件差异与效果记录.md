# Typecho Workers V7 图片显示修复：文件差异与效果记录

## 1. 文档目的

本文记录为改善 Typecho Workers V7 主题中文章图片显示问题而进行的两处文件修改，说明修改前后的差异、作用、配合关系以及后续维护时需要注意的事项。

## 2. 对比基准与涉及文件

本次修改涉及两个文件：

| 文件 | 主要职责 | 本次修改目标 |
|---|---|---|
| `style.css`（或项目中实际使用的主题样式文件） | 控制文章正文图片的尺寸与布局 | 避免图片超出正文区域，改善图片高度与宽度的自适应表现 |
| `src/lib/image-transform.ts` | 处理文章 HTML 中的图片标签及图片优化 URL | 从图片 URL 的片段参数中识别尺寸，并在图片标签缺少尺寸属性时补充 `width`、`height` |

对比时应以实际使用的 V7 原始文件和修改后的文件为准。若项目中的文件名、目录或内容与此处不同，请以仓库中的真实路径为准。

## 3. CSS 修改记录

### 3.1 为笔记正文图片增加自适应约束

新增规则：

```css
.warm-note__content img {
  max-width: 100%;
  height: auto;
}
```

**修改作用：**

- `max-width: 100%`：限制图片最大宽度不超过正文容器。
- `height: auto`：在图片缩放时按原始比例调整高度，避免因固定高度导致图片变形。
- 规则针对 `.warm-note__content` 内的图片，不会直接作用于整个网站所有图片。

**预期效果：** 笔记类内容中的大图更容易在窄屏或较窄的正文容器内正常显示。

### 3.2 调整正文 figure 图片的宽度约束

原规则使用 `width: 100%`，修改后使用：

```css
.warm-prose figure img {
  max-width: 100%;
  height: auto;
}
```

**主要差异：**

- `width: 100%` 会要求图片宽度占满可用区域。
- `max-width: 100%` 只限制图片不能超过容器，允许图片按自身尺寸显示；当图片比容器宽时才缩小。
- `height: auto` 用于保持宽高比例。

**预期效果：** 对本身尺寸较小的图片，不再一律强制拉伸到整个 figure 宽度；较大的图片仍受到容器宽度限制。

### 3.3 缩小特定正文图片规则的匹配范围

选择器从：

```css
.warm-article:not(.is-note) .warm-prose img
```

调整为：

```css
.warm-article:not(.is-note) .warm-prose img:not([width][height])
```

**主要差异：**

新选择器只匹配没有同时具备 `width` 和 `height` 属性的图片。具有这两个属性的图片不会命中这条特定规则。

**为什么这样做：**

如果图片标签已经携带宽高属性，CSS 仍可能对它应用额外的定位或布局行为，从而影响浏览器依据宽高属性预留空间、计算图片比例或展示图片的方式。缩小选择器范围可以避免这条特定规则继续作用于同时具有 `width`、`height` 的图片。

**注意：** `:not([width][height])` 的含义是“缺少 width 或缺少 height，或两者都缺少”。它不是“只要有任意一个尺寸属性就排除”。

## 4. TypeScript 修改记录

涉及文件：`src/lib/image-transform.ts`

### 4.1 从只替换图片 URL 改为处理完整的 `<img>` 标签

原处理方式主要针对图片标签中的 `src` 内容进行替换。修改后，处理逻辑会匹配完整的 `<img ...>` 标签。

**作用：**

- 可以同时读取图片标签中的现有属性。
- 可以判断 `width`、`height` 是否已经存在。
- 能在保留原标签其他属性的前提下，补充缺失的尺寸属性。

### 4.2 从 URL 片段中解析尺寸信息

图片 URL 可能包含类似以下片段：

```text
#width=1200&height=800
```

处理逻辑会尝试从 URL 的 `#` 片段中读取宽度和高度信息，并兼容 HTML 属性中可能出现的 `&amp;` 写法。

例如：

```html
<img src="https://example.com/photo.jpg#width=1200&amp;height=800" alt="示例图片">
```

在这种情况下，解析逻辑可以尝试提取 `width=1200` 和 `height=800`，供后续补充属性使用。

**边界说明：** 只有 URL 中实际存在可识别的尺寸参数时，才能从该片段提取尺寸；没有尺寸参数时，不能凭空推断原图尺寸。

### 4.3 新增 `getDimension()` 尺寸校验逻辑

新增的尺寸读取辅助逻辑用于校验解析出的宽度或高度。有效值要求为正整数，并且不超过 `10000`。

这可以过滤掉以下不合适的值：

- 空字符串或无法转换为数字的内容；
- 零或负数；
- 小数或其他非正整数格式；
- 过大的异常数值。

**作用：** 避免将明显无效的 URL 参数直接写入 HTML 图片属性。

### 4.4 仅补充缺失的 `width` 和 `height`

修改后的逻辑会检查图片标签是否已经存在宽高属性：

- 缺少 `width` 时，且解析到有效宽度，才补充 `width`。
- 缺少 `height` 时，且解析到有效高度，才补充 `height`。
- 已有的 `width` 或 `height` 不会被新解析值覆盖。
- 如果没有解析到有效尺寸，则不应凭空添加尺寸属性。

这样可以尽量保留文章原有 HTML 的设置，降低对旧文章图片的影响。

**重要限制：** 如果原文章中已有错误的宽高属性，本次逻辑不会自动纠正它们，因为设计目标是补缺而非覆盖。

### 4.5 将属性插入图片标签结束符之前

补充属性时，需要把新属性放在 `>` 或自闭合写法 `/>` 之前，避免将属性错误地追加到标签结束符之后。

例如，原标签：

```html
<img src="https://example.com/photo.jpg" alt="示例图片">
```

在解析到有效尺寸且标签缺少相应属性时，结果可能类似：

```html
<img src="https://example.com/photo.jpg" alt="示例图片" width="1200" height="800">
```

实际补充哪些属性，取决于 URL 中解析到的有效尺寸以及原标签已有的属性。

### 4.6 保留原有图片优化流程

本次尺寸处理修改不应被理解为替换整套图片优化机制。原有的 `normalizeOptimizeParams` 和 `optimizeImageUrl` 逻辑继续负责原本的图片优化参数规范化及 URL 优化工作。

换言之，修改重点是：在处理图片标签时补充可用的尺寸信息，同时保留原有图片 URL 优化行为。

## 5. 两个文件如何配合

| 环节 | TypeScript 处理 | CSS 处理 |
|---|---|---|
| 读取图片标签 | 识别完整 `<img>` 标签 | 不负责解析 HTML |
| 读取 URL 尺寸参数 | 尝试提取有效的宽高 | 不负责解析 URL 片段 |
| 补充图片属性 | 只补充缺失且可确认的宽高 | 根据图片和容器尺寸进行布局 |
| 防止图片溢出 | 不是主要职责 | 使用 `max-width: 100%` 限制图片宽度 |
| 保持图片比例 | 通过宽高属性帮助浏览器理解比例 | 使用 `height: auto` 配合自适应布局 |
| 图片优化 | 保留原有优化 URL 逻辑 | 不负责生成优化 URL |

两处修改分别解决不同层面的问题：TypeScript 侧尝试补充图片尺寸元数据，CSS 侧控制图片在正文容器中的显示方式。它们配合使用，但互不替代。

## 6. 预期改善与不能保证的事项

| 情况 | 预期改善 | 仍需注意 |
|---|---|---|
| 图片宽度大于正文容器 | CSS 限制图片最大宽度 | 其他更高优先级的 CSS 仍可能覆盖规则 |
| 图片本身尺寸较小 | `max-width` 避免一律强制撑满 | 其他样式仍可能设置固定宽度 |
| URL 片段带有有效宽高 | 可以尝试将尺寸补充到图片标签 | 参数格式不受支持或缺失时无法提取 |
| 图片标签缺少宽高属性 | 可补充已解析到的有效尺寸 | 不会从图片文件内容中实际读取原图尺寸 |
| 图片标签已有宽高属性 | 尽量保留原有属性 | 已有的错误尺寸不会自动修复 |
| 图片 URL 优化 | 保留原优化函数的职责 | 不能据此保证每种图床、每种 URL 格式都兼容 |
| Markdown 展示问题 | 图片布局可能得到改善 | 不等于修复所有 Markdown 语法或渲染问题 |

## 7. 验证建议

修改并部署后，建议至少测试以下场景：

1. **宽图：** 图片宽度明显大于正文容器，确认不会横向溢出。
2. **小图：** 原图尺寸较小，确认不会被强制拉伸到整行。
3. **带尺寸参数的 URL：** 检查 `#width=...&height=...` 能否正确识别。
4. **HTML 转义参数：** 检查 `&amp;` 形式是否能正确解析。
5. **已有宽高属性：** 确认原有 `width`、`height` 不会被覆盖。
6. **只有一个尺寸属性：** 确认只补充缺失且有效的另一个属性。
7. **无尺寸参数的 URL：** 确认不会写入猜测出来的宽高。
8. **移动端：** 在窄屏设备上检查图片、figure 和正文容器的布局。
9. **原有优化功能：** 确认图片 URL 优化仍正常工作。

建议同时检查浏览器开发者工具中的最终 HTML 与计算样式，以区分问题来自 HTML 属性、CSS 规则还是图片服务本身。

## 9. 总结

本次修复的核心思路是：

1. **CSS 层：** 将部分图片宽度规则从强制铺满调整为最大宽度约束，并补充 `height: auto`，同时缩小一条正文图片规则的匹配范围。
2. **TypeScript 层：** 从图片 URL 片段中尝试解析有效宽高，在不覆盖已有属性的前提下补充缺失的 `width`、`height`。
3. **兼容性层：** 保留原有图片优化函数的职责，尽量减少对既有文章 HTML 的改动。

这份记录描述的是修改意图和预期效果。若要形成严格的逐行差异审计，应以原始 V7 文件和最终修改文件实际执行 diff 的结果为准；仅凭本说明不能替代逐行源码比对。
