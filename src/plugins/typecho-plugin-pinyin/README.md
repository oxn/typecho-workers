# 拼音别名插件

根据文章或独立页面标题，在编辑器中自动生成 ASCII 拼音别名建议。插件只负责提供建议值；最终仍由原有编辑器表单和内容保存流程保存别名。

## 1. 插件如何被引入和加载

本插件是仓库内的 workspace 插件，目录为 `src/plugins/typecho-plugin-pinyin/`。

引入链路如下：

1. 根目录 `package.json` 的 `workspaces` 包含 `src/plugins/*`，并在 `dependencies` 中声明 `typecho-plugin-pinyin: workspace:*`。
2. 插件自己的 `package.json` 使用 `keywords: ["typecho", "plugin", ...]` 标识插件，并在 `typecho.plugin` 中声明插件 ID、名称等元数据。
3. 构建阶段的插件加载器扫描本地 workspace 依赖，读取插件清单并寻找入口文件（本插件入口为 `index.ts`）。
4. 插件注册到系统插件注册表后，是否执行其 Hook 仍由后台的插件启用状态决定；未启用的插件不会执行初始化逻辑。
5. 插件通过 `typecho/plugin-sdk` 注册编辑器 Hook 和请求路由，不需要修改主题文件或核心编辑器文件。

插件入口使用 `export default init(...)`，通过 `addHook` 注册功能。拼音转换依赖 `pinyin-pro`，在 Worker 本地执行，不从第三方 CDN 加载拼音库。

## 2. 作用范围与启用条件

插件只处理：

- 文章编辑器的标题和别名字段；
- 独立页面编辑器的标题和别名字段。

插件分别读取文章永久链接格式 `permalinkPattern` 和独立页面链接格式 `pagePattern`：

- 文章链接格式包含 `{slug}` 时，才向文章编辑器注入拼音辅助功能。
- 独立页面链接格式包含 `{slug}` 时，才向页面编辑器注入拼音辅助功能。
- 对应链接格式不包含 `{slug}` 时，不注入该编辑器的辅助代码。

插件不会替用户修改站点的永久链接格式。若看不到拼音功能，先检查对应的文章或独立页面链接格式是否使用了 `{slug}`，再检查插件是否已启用。

## 3. 自动生成、原有别名与手动操作

### 新建文章或页面

- 新建内容时，如果别名字段为空，插件会根据标题自动生成建议。
- 输入标题后会稍作延迟再请求生成，避免每敲一个字符都立即发送请求。
- 如果新建时别名字段已经有内容，插件将其视为用户已有输入，不会自动覆盖。

### 编辑已有内容

- 编辑已有文章或页面时，插件默认将别名视为需要保护的既有值，不会因为标题变化而自动改写。
- 标题修改不会自动改变原有别名，避免既有文章 URL 因编辑标题而变化。
- 手动编辑别名后，自动生成也会停止，不会抢回字段控制权。

### 重新生成拼音

编辑器别名字段旁提供「重新生成拼音」按钮。点击后才会明确要求插件根据当前标题重新生成，并替换别名字段中的现有值。

请注意：重新生成是主动覆盖操作。若文章已经发布，修改别名可能改变文章 URL；是否设置重定向取决于站点现有的链接与重定向管理方式，本插件不会自动创建旧 URL 到新 URL 的重定向。

## 4. 汉字生成规范

转换由服务端的 `titleToPinyinSlug()` 完成，使用 `pinyin-pro`：

- 连续汉字的拼音音节直接连接，不在每个汉字或每个音节之间插入连字符。
- 不保留声调。
- 转换结果统一为小写 ASCII 字母和数字。
- 拼音中的组合音调符号会经过 Unicode 规范化处理。
- 生成结果最长为 180 个字符。

示例：

| 原标题 | 生成别名 |
|---|---|
| 中华人民共和国 | `zhonghuarenmingongheguo` |
| 你好世界 | `nihaoshijie` |
| 我的文章：标题 | `wodewenzhang-biaoti` |

## 5. 汉字、英文、数字混合生成规范

插件按原始标题中的空白、Unicode 标点和符号切分片段，再分别转换并拼接：

- 连续汉字片段生成连续拼音。
- 英文片段保留其字母内容并统一小写。
- 数字保留为数字。
- 汉字与英文/数字之间如果原文没有分隔符，不会凭空添加单词边界连字符；原文有空格或标点时，才会形成连字符分隔。
- 转换后不属于 ASCII 字母或数字的内容会被规范化为分隔符。

示例：

| 原标题 | 生成别名 |
|---|---|
| 你好 Typecho | `nihao-typecho` |
| Typecho 主题 2026 | `typecho-zhuti-2026` |
| Hello, World! | `hello-world` |
| 我的文章：Typecho 标题 | `wodewenzhang-typecho-biaoti` |

这里的“混合”是指汉字、拉丁字母和数字在同一标题中的普通混合，不是引用内容识别或语义分词。

## 6. 带引号、书名号及其他符号的标题

空格、换行、标点和 Unicode 符号统一作为分隔符处理：

- 连续的分隔符合并成一个 `-`。
- 生成结果开头和结尾不会保留 `-`。
- 中文引号、英文引号、书名号、括号、破折号、冒号、问号、感叹号等没有各自独立的特殊转换规则；它们都按分隔符处理。
- 引号或书名号包住的汉字仍按普通汉字转换，不会因为被引用而改变拼音。
- 符号本身不会进入最终别名。

示例：

| 原标题 | 生成别名 |
|---|---|
| 《你好世界》 | `nihaoshijie` |
| “你好” Typecho | `nihao-typecho` |
| 【年度总结】2026！ | `nianduzongjie-2026` |
| 你好——世界 | `nihao-shijie` |

因此，带符号标题的生成规则可以概括为：**保留文字内容，符号作为分隔边界，不把符号翻译或写入别名。**

## 7. 生成请求与安全

浏览器编辑器只把标题发送到插件专用路由 `POST /api/admin/pinyin-slug`，拼音转换在 Worker 内完成。

请求处理包含以下限制：

- 只接受 POST；其他方法返回 405。
- 使用系统现有的管理员操作权限校验，要求具备编辑权限。
- 沿用系统管理员操作的同源和 CSRF 安全校验。
- 标题必须是非空字符串，且长度不能超过 500 个字符。
- 响应设置 `Cache-Control: private, no-store`，不缓存个人编辑请求结果。
- 生成失败属于编辑器辅助功能失败，不会阻止文章或页面保存。

## 8. 与原有系统的边界

本插件只在编辑器中生成并填入别名建议，不接管别名保存流程：

- 不修改核心编辑器、保存 API、数据库结构或主题文件。
- 不修改站点永久链接设置。
- 不自动批量修改历史文章或页面的别名。
- 不自动覆盖编辑中的既有别名。
- 不改变标签等其他内容类型的 slug 生成规则。
- 最终别名仍通过原有编辑表单提交，并由原有保存逻辑处理重名和唯一性问题。
- 插件不负责创建 URL 重定向。

## 9. 常见问题排查

**编辑器里没有出现拼音辅助功能**

1. 确认「拼音别名」插件已启用。
2. 检查文章永久链接格式或独立页面链接格式是否包含 `{slug}`。
3. 确认当前打开的是文章编辑器或独立页面编辑器。

**修改标题后原来的别名没有变化**

这是预期保护行为。编辑已有内容时默认不自动覆盖原别名。如确实需要更新，请主动点击「重新生成拼音」。

**新建内容时没有自动填入**

检查别名字段是否已经有值。新建时非空别名会被视为已有输入并受到保护。

**生成请求失败**

拼音建议是可选的编辑器增强功能。请求失败不会阻止正常保存；可检查管理员登录状态、编辑权限、同源/CSRF 校验及浏览器网络请求。

## 10. 测试覆盖

同目录的 `index.test.ts` 覆盖：

- 连续汉字拼音拼接与原文分隔符规则；
- 汉字和英文混合标题；
- 标点与空白归一化；
- 仅在永久链接格式包含 `{slug}` 时注入编辑器辅助功能；
- 编辑已有内容时保护别名，以及手动重新生成入口；
- 拼音路由只接受 POST；
- 管理员编辑权限校验；
- 非法 JSON、空标题和超长标题校验；
- 安全校验通过后返回生成结果。

运行单个插件测试：

```sh
bunx vitest run src/plugins/typecho-plugin-pinyin/index.test.ts
```
