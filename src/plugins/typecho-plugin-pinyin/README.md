# 拼音别名插件

**插件版本：** 1.0.1（以 `package.json` 为准）  
**插件 ID：** `typecho-plugin-pinyin`  
**适用对象：** 文章编辑器、独立页面编辑器  
**拼音依赖：** `pinyin-pro`（依赖声明 `^3.29.5`；当前锁定版本为 `3.29.5`）

## 1. 插件用途

拼音别名插件根据文章或独立页面的标题生成 URL 安全的 ASCII 别名建议，并将建议填入编辑器的别名输入框。

插件同时提供手动编辑、主动重新生成、标题长度限制、别名长度限制和别名冲突处理。它不负责修改站点永久链接规则，也不批量改写已有文章或页面。

## 2. 工作位置与执行架构

插件位于 `src/plugins/typecho-plugin-pinyin/`，由项目现有 workspace 插件加载机制发现和注册。

主要文件：

- `package.json`：插件元数据、版本、设置项和依赖声明。
- `index.ts`：服务端插件入口；注册后台编辑器 Hook、保存完成 Hook，并输出编辑器辅助脚本。
- `client/pinyin-editor.ts`：浏览器端拼音转换函数；调用 `pinyin-pro` 并挂载 `window.TypechoPinyinSlug`。
- `index.test.ts`：插件行为测试。
- `README.md`：本说明文档。
- `THIRD-PARTY-NOTICES.md`：第三方依赖许可证及版权声明。

执行分工：

1. 插件入口通过 `admin:writePost:bottom` 和 `admin:writePage:bottom` Hook，将编辑器辅助代码注入文章和独立页面编辑界面。
2. 项目的客户端加载器负责构建 `client/pinyin-editor.ts`，编辑器引用插件资源路径 `/plugin-assets/typecho-plugin-pinyin/pinyin-editor.js`。
3. 标题转拼音在用户浏览器中执行。浏览器使用已打包的 `pinyin-pro`，不请求第三方 CDN，也不向 Worker 发送标题以请求拼音转换。
4. 用户提交内容时，编辑器将当前别名放入保存请求的 `__pinyinSlug` 查询参数。
5. 插件通过 `post:finishSave` 和 `page:finishSave` Hook，在文章或页面核心保存完成阶段处理提交的别名、规范化及重名冲突。
6. 插件不替换核心内容保存接口，也不改变数据库表结构。

因此，拼音转换属于客户端工作；保存后的别名规范化和唯一性处理属于服务端保存 Hook。两者职责不同，不应将拼音转换误描述为服务端接口。

## 3. 编辑器行为

### 新建文章或独立页面

- 标题输入框受到「文章、页面标题长度」设置限制。
- 标题框失去焦点（`blur`）后，若别名为空且没有被用户手动接管，浏览器生成拼音建议。
- 输入标题的过程中不会逐字实时生成。
- 如果别名输入框已有内容，插件会将其视为已有值，不主动覆盖。

### 编辑已有文章或独立页面

- 已有别名默认受到保护。
- 只修改标题不会自动改变原有别名，避免因标题编辑意外改变已发布内容的 URL。
- 用户可以手动编辑别名。
- 点击「重新生成」会明确要求插件根据当前标题重新生成，并替换当前别名。

重新生成属于主动覆盖操作。对于已经发布的内容，修改别名可能改变 URL；插件不会自动创建旧 URL 到新 URL 的重定向。

## 4. 永久链接模式

插件兼容文章和独立页面各自的永久链接设置。

### 永久链接包含 `{slug}`

- 使用系统原有别名输入框。
- 插件在该输入框中生成或编辑别名。
- 当永久链接模式允许编辑 slug 时，编辑器会显示 CID 辅助信息。

### 固定 CID 等不包含 `{slug}` 的永久链接

- 插件在永久链接区域补充别名输入框，使用户仍可维护文章或页面的 slug。
- 保存时通过 `__pinyinSlug` 参数把别名交给保存完成 Hook。
- **不额外显示 CID 文本**：CID 已经体现在永久链接中，再显示一次没有必要。这是文章和独立页面一致采用的设计。

插件不会更改永久链接格式，也不会把别名强行加入当前永久链接。

## 5. 拼音生成规则

浏览器端的 `titleToPinyinSlug()` 使用 `pinyin-pro` 生成拼音，主要规则如下：

- 不保留声调。
- 连续汉字转换为连续拼音音节，不在每个汉字之间插入连字符。
- 原标题中的空格、Unicode 标点和符号作为分隔边界。
- 连续分隔符合并为一个连字符 `-`。
- 英文字母和数字按原有内容保留，并统一为小写。
- 拼音结果进行 Unicode 规范化，移除组合音调符号。
- 最终只保留 ASCII 小写字母、数字和连字符。
- 结果首尾不保留连字符，并按设置的最大长度截断。

示例：

| 原标题 | 生成别名 |
|---|---|
| 中华人民共和国 | `zhonghuarenmingongheguo` |
| 你好世界 | `nihaoshijie` |
| 我的文章：标题 | `wodewenzhang-biaoti` |
| 你好 Typecho | `nihao-typecho` |
| Typecho 主题 2026 | `typecho-zhuti-2026` |
| Hello, World! | `hello-world` |
| 《你好世界》 | `nihaoshijie` |

上述规则是字符转换和分隔符处理，不是语义分词，也不判断标题中英文单词的语义边界。

## 6. 插件设置

插件设置页提供以下三项：

| 设置项 | 默认值 | 允许范围 | 作用 |
|---|---:|---:|---|
| 文章、页面标题长度 | 100 | 1–500 | 限制编辑器标题输入长度 |
| 拼音别名最大长度 | 300 | 1–1000 | 限制别名输入、生成和保存规范化后的长度 |
| 别名重复测试次数 | 50 | 1–200 | 限制服务端处理别名冲突时的尝试次数 |

配置值会被转换为整数并限制在允许范围内；无效值使用默认值。

## 7. 保存与别名冲突处理

客户端负责生成和编辑别名；服务端保存 Hook 负责最终处理：

1. 从内容保存请求中读取 `__pinyinSlug`。
2. 对提交值进行去空白、Unicode 规范化、小写化和 URL 安全字符处理。
3. 根据当前内容 CID 尝试写入别名。
4. 如果别名已被其他内容占用，则按配置的尝试次数追加 CID/尝试序号后重试。
5. 最后一次尝试使用 CID 与时间信息构造后备后缀。
6. 数据库更新通过条件判断排除其他内容已占用的 slug，成功后更新本次保存对象中的 slug 值。
7. 超过最大尝试次数仍无法取得唯一别名时，保存 Hook 抛出冲突错误，提示用户修改别名后重试。

文章和独立页面分别通过 `post:finishSave`、`page:finishSave` Hook 使用同一套处理逻辑。

## 8. 与系统其他部分的边界

本插件只处理文章和独立页面编辑器中的别名辅助功能：

- 不修改主题文件。
- 不修改核心编辑器文件。
- 不修改核心内容保存 API 的实现。
- 不修改数据库结构。
- 不修改站点永久链接配置。
- 不批量修改历史文章或页面。
- 不自动覆盖已有别名。
- 不改变标签等其他内容类型的 slug 规则。
- 不创建 URL 重定向。
- 不依赖第三方 CDN 提供拼音脚本。

插件的后台设置样式由插件入口通过 Hook 注入，不另行追加主题 CSS。

## 9. 故障排查

**编辑器没有出现拼音辅助功能**

1. 确认后台已启用「拼音别名」插件。
2. 确认当前页面是文章编辑器或独立页面编辑器。
3. 检查构建产物是否包含 `public/plugin-assets/typecho-plugin-pinyin/pinyin-editor.js`。
4. 浏览器开发者工具中检查该插件资源是否成功加载。

**标题修改后别名没有自动变化**

这是保护既有别名的预期行为。请确认别名字段是否已有值；如确实需要替换，使用「重新生成」。

**标题输入后没有自动生成**

标题框失去焦点后才触发生成。检查别名是否已有内容，以及客户端插件资源是否成功加载。

**保存时提示别名冲突**

说明在允许的重试次数内未能取得唯一别名。请修改别名，或检查站点中是否存在重复的 slug。

## 10. 测试

运行插件测试：

```sh
bunx vitest run src/plugins/typecho-plugin-pinyin/index.test.ts
```

当前 `index.test.ts` 实际覆盖：

- 拼音转换示例及空标题处理；
- 默认 300 字符上限和自定义别名长度；
- 文章、独立页面编辑器的客户端脚本注入；
- 标题失焦触发生成、使用浏览器拼音函数，且不发起拼音生成请求；
- 默认标题长度、别名长度配置；
- 文章和页面的保存完成 Hook 存在，且没有注册拼音生成 API 路由。

**当前测试没有直接覆盖数据库重名竞争、保存 Hook 的完整写入过程或所有配置边界**；这些行为不能仅凭现有测试声称已得到自动化验证。

## 客户端资源构建

拼音编辑器脚本由本插件独立构建，不再经过系统全局 client-loader，也不会输出到 `public/plugin-assets/`。Astro 的插件构建集成会在 `astro build` 和 `astro dev` 配置阶段自动生成 `client/dist/pinyin-editor.js`，不依赖 workspace `postinstall`；也可以在插件目录执行 `bun run build:client` 手动构建。插件通过自身的 `route:request` 路由提供浏览器脚本。
