## 1. 图片分类与尺寸：本地场景验证

用户已在本地构建并启动 Workers。构建成功，Markdown Rehype 的客户端脚本均已打包，Workers 本地服务正常启动。

以下结果来自用户实际页面测试，不等同于自动化测试或 Rin 全量对照：

| 文章正文场景 | 用户实测尺寸比例 | 用户实测圆角 |
|---|---:|---|
| 文章开头的首张图片 | 0.75 | 当时观察为有圆角；后续发现该观察可能混入首页展示样式，见第 2 节 |
| 正文句子中的行内图片 | 0.5 | 无 |
| 连续图片第一张 | 0.75 | 当时观察为有圆角；后续圆角结论待重新核实，见第 2 节 |
| 连续图片第二张 | 0.5 | 无 |
| 普通文字段落后空一行的独立图片 | 0.75 | 无 |

### 已确认事项

- 用户实际验证的上述场景中，0.75 / 0.5 尺寸分类符合预期。
- 图片尺寸比例指图片实际显示尺寸，不是 Markdown 输入尺寸。
- 当前图片分类和尺寸表现暂不调整。
- 不得为了处理圆角问题而改变已验证的分类逻辑或 0.75 / 0.5 比例。

## 2. 图片圆角问题：未决，明确冻结

这是一个曾被错误判断、后来又补充了新观察的事项，必须保留完整上下文：

1. 最初在一篇文章中测试时，用户观察到：文章开头图片 0.75 且有圆角；正文行内图片 0.5 且无圆角；连续图片第一张 0.75 且有圆角、第二张 0.5 且无圆角。
2. 对“首图有圆角、段落后独立图片无圆角”的差异，助手曾错误地把 Rin 网站首页的图片展示样式当成文章正文样式来比较。
3. 用户明确纠正：Rin 首页展示图片的样式，不等于 Rin 文章正文内部图片的样式；不能把首页圆角规则直接套用到文章正文。
4. 用户随后又补充：检查其他文章后，发现文章正文里也有圆角，而且有些带圆角的图片并不是首张图片。
5. 因此，目前不能得出“文章正文只有首图有圆角”“文章正文全部没有圆角”或“所有 0.75 图片都有圆角”等规则。现有观察不足以确认圆角究竟由图片位置、Markdown 结构、文章内容差异、历史 HTML 或其他样式条件决定。

### 当前决定（用户明确要求）

- **当前图片样式先保持原样，不要修改；以后用户提出时再讨论。**
- 本事项暂时冻结，不得自行调整 CSS、运行时圆角判断或图片 DOM。
- 后续若重新启动调查，必须分别比较 Rin 网站首页、Rin 文章正文，以及插件在多篇文章中的实际 DOM / class / computed style；不能只用“首图/非首图”推断。
- 在获得可复现证据和用户明确同意前，不提交圆角修正。

## 3. 图片分类相关实现记录

- 图片分类回归测试曾补充文章首图、正文行内图片、连续图片及段落后独立图片等场景。

## 7. Markdown 表格满铺修正（2026-11-17）

- 只读检查主题样式发现 `.warm-prose table` 使用 `width: max-content !important`，文章表格还会经过主题的 breakout 规则；插件原来把满铺覆盖单独放在文件末尾的 `.warm-prose .toc-content table` 规则中，导致规则分散且只针对该外层结构。
- 已将满铺约束合并回插件原有的通用 `.toc-content table` 规则：加入 `box-sizing: border-box`、`width: 100% !important`、`min-width: 100%`、`max-width: 100%`，并移除末尾重复的专用覆盖规则。未修改主题文件、Markdown 解析结构或表格颜色规则。
- 该修改确保表格至少铺满 Markdown 内容容器的可用宽度；超出容器的内容仍由表格自身横向滚动承载。尚未经过用户本地浏览器视觉验收，不记为显示测试通过。
