# Warm CY 配套插件

Warm CY Companion 为 `typecho-theme-warm-cy` 提供配套管理接口、后台功能开关和前台增强。插件 ID：`typecho-plugin-warm-cy`。

本说明以当前稳定版插件源码为准。npm/workspace 插件版本：`1.2.0`；package buildVersion：`2026.11.10.21.20`；后台功能页显示的源码版本标记：`2026.11.10.21.03`。这三个标记用途不同，不应互相覆盖。

## 一、插件引入与生效机制

### 1. 插件如何被项目加载

- 插件位于 `src/plugins/typecho-plugin-warm-cy/`，由项目的插件 workspace / 构建流程发现和打包。
- `package.json` 中的 `typecho.plugin.id` 为 `typecho-plugin-warm-cy`，这是插件注册和识别使用的 ID；不要用显示名称代替。
- 插件被构建、注册不等于功能必然运行：仍需在后台启用插件。停用后，插件注册的 hooks、路由和 early-request provider 不再参与请求处理。
- 插件通过默认导出的 `init({ addHook, pluginId })` 注册功能，并注册两个插件管理路径：`/api/admin/theme-pin` 和 `/api/admin/cy-companion-settings`。
- 前台主题相关界面只在当前主题为 `typecho-theme-warm-cy` 时增强。切换到其他主题后，CY 专属搜索入口、Alert 样式、主题设置界面装饰和评论管理元数据不会按 Warm CY 方式输出。

### 2. 插件设置保存在哪里

插件自己的功能开关和 Alert 样式统一保存在 D1 options 的私有插件选项：

```
plugin:typecho-plugin-warm-cy
```

置顶文章 ID 列表则沿用 Warm CY 主题原有设置，保存在：

```
theme:typecho-theme-warm-cy
```

这两类数据有意分开：插件功能设置归插件管理；`pinnedIds` 属于主题首页展示配置，不另建一份重复的置顶配置。设置保存使用项目的插件 SDK / options 接口，不需要手动改数据库。

## 二、后台入口与设置管理

### 1. CY 功能显示页面

后台入口名称为 **CY 功能显示**，页面路径：

```
/admin/plugin/cy-companion
```

在 Warm CY 主题启用时，插件会把入口加入后台“设置”菜单；如果后台菜单结构不符合预期，也会尝试放到主菜单中。Warm CY 的“设置外观”页面标题区域也会显示快捷入口。

页面中的开关和 Alert 样式集中保存到插件私有设置中。保存请求使用 POST：

```
/api/admin/cy-companion-settings
```

服务端要求管理员身份，并经过项目现有的管理员操作校验；只接受 POST 和合法的 JSON / 设置值。保存时会合并现有插件设置，避免把其他未参与本次表单的设置字段一并清掉。

### 2. 设置项一览

| 功能 | 设置项 | 默认状态 | 管理位置 |
|---|---|---|---|
| 评论区管理按键 | `showCommentManagementButtons` | 开启 | CY 功能显示 |
| 首页搜索按键 | `showHomeSearchButton` | 开启 | CY 功能显示 |
| 正文 HTML / CSS / JavaScript 增强 | `htmlEnhancementEnabled` | 关闭 | CY 功能显示 |
| 备用域名跳转主域名 | `canonicalDomainRedirectEnabled` | 关闭 | CY 功能显示 |
| 五种 Markdown Alert 样式 | `markdownAlertStyleSettings` | 样式开关默认开启 | CY 功能显示 |
| 首页置顶文章 | 主题设置中的 `pinnedIds` | 由主题原有配置决定 | 外观设置 |

## 三、各项功能的实现与使用说明

### 1. 评论区管理按键

- 作用范围是文章和独立页面的评论区；仅向已通过管理员身份校验的请求附加管理元数据。
- 插件通过 `comment:list` hook 判断当前主题、内容 ID 和内容类型，再附加 `canManage`、`showManagementButtons`、内容类型、置顶状态、后台地址及安全令牌等信息，供 Warm CY 主题显示相应管理操作。
- `showCommentManagementButtons` 只控制前台是否显示管理按键。关闭后隐藏按钮，但不改变后台管理员权限，也不代表管理 API 被关闭。
- 匿名访客不会得到评论管理元数据；非文章/独立页面内容也不会进入这套管理逻辑。

### 2. 首页搜索按键

- `showHomeSearchButton` 控制 Warm CY 页面主导航中的全局搜索入口。
- 开启时，插件在页面 footer 注入搜索脚本，按需创建搜索按钮和对话框；搜索关键词为空时提示输入，提交后跳转到站点搜索地址。
- 搜索地址从当前站点的 `siteUrl` 计算，不把域名写死在插件中。
- 插件会兼容页面导航区域不存在的情况，将按钮放到页头或浮动位置；也会监听主题的页面切换事件，重新确保搜索控件存在。
- 关闭后不创建搜索入口和对话框。此开关只控制 Warm CY 的这套搜索 UI，不会修改 Typecho 的搜索数据或搜索接口。

### 3. 正文 HTML / CSS / JavaScript 增强

此功能默认关闭，设置项为 `htmlEnhancementEnabled`。开启后，文章和独立页面正文可按插件的保护、清理和恢复流程使用部分原始 HTML 能力，包括：

- HTML 元素的 `class`、`id`、`data-*`、`aria-*` 和受支持的 `style` 等属性；
- 内嵌 `<style>`、`<script>`；
- SVG 图形；
- 受允许列表约束的 iframe、音视频及其他 HTML 片段。

实现流程不是直接跳过清理：插件先在 Markdown 处理前保护需要保留的 HTML 片段，再在内容输出阶段按允许列表清理并恢复；内嵌 CSS 会限制在文章正文区域，SVG 会经过单独的节点和属性白名单处理。脚本按内容顺序加入执行队列。插件对 iframe 主机名也有限制，当前允许列表包含 YouTube、YouTube NoCookie、Bilibili 播放器和 Vimeo 播放器；这不等于任意外站 iframe 都可用。

**重要安全提醒：开启后，正文中允许通过检查的脚本会在访客浏览器中执行。** 只应在文章发布者可信、权限管理明确的站点开启。不要把它当作通用 HTML 消毒器，也不要将不可信用户提交的内容视为安全。此功能只处理文章和独立页面正文；笔记由独立笔记插件处理，评论区不在此功能范围内。

### 4. Markdown Alert（NOTE / TIP / IMPORTANT / WARNING / CAUTION）样式

插件提供五类 GitHub 风格 Markdown Alert 的外观设置：

- `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 分别设置背景色、边框色、标题色、正文色、图标色、圆角和边框样式。
- 边框样式可选 `solid`、`dashed`、`dotted`、`double`、`none`。
- 可统一控制 SVG 图标显示、图标尺寸（12–32 px）和图标与标题的间距（0–20 px）。
- “恢复默认样式”恢复插件内置的五类预设值；需要再点击“保存设置”才会保存。
- 关闭 Alert 样式总开关后，插件不输出这套自定义样式，页面回到主题原生 Note 样式。

**边界：** 此模块只负责已被 Markdown 解析器识别出的 Alert 呈现样式和图标恢复，不负责改变 Markdown 语法、解析器或 Alert 类型识别规则。它不会把普通引用块自动转换成 Alert。

### 5. 首页置顶文章管理

置顶数据沿用 Warm CY 主题原有的 `pinnedIds`，不是 CY 插件页面中的另一套独立配置。

- 主题设置页中的置顶文章字段仍是数据管理入口；插件只负责把相关字段整理到主题设置卡片中，并提供配套管理接口。
- `pinnedIds` 支持逗号、中文逗号或空白分隔；解析时会忽略无效、非正整数和重复 ID。
- 管理接口为 `POST /api/admin/theme-pin`，必须是管理员请求，并要求请求体包含有效文章 ID、布尔值 `pinned` 和确认文本 `confirmation: "确认"`。
- 只能置顶或取消置顶已发布的文章（`type=post` 且 `status=publish`）；独立页面、草稿、已删除或不存在的内容不会被作为有效置顶文章处理。
- 写入时更新的是 `theme:typecho-theme-warm-cy` 中的 `pinnedIds`，并保留同一主题设置对象里的其他字段。

不要在插件设置中另建一份置顶 ID 列表，也不要直接编辑数据库来维护置顶文章。

### 6. 备用域名自动跳转到主域名

设置项为 `canonicalDomainRedirectEnabled`，默认关闭。

- 开启后，插件读取项目基本设置中的站点地址 `siteUrl` 作为当前主域名目标；不在 CY 插件中重复维护一份主域名。
- 对备用域名上的公开 GET / HEAD 请求，返回临时 302 跳转，并保留原请求路径和查询参数。
- 目标域名或协议已经与 `siteUrl` 一致时，不重复跳转。
- 后台、API、安装路径、主题/插件资源目录、上传目录、常见静态文件及其他列入排除规则的资源路径不会被跳转。
- 跳转响应带有 `Cache-Control: no-store`，避免浏览器或 CDN 长期缓存永久跳转。
- 修改主域名时应先确认基本设置中的 `siteUrl` 正确，并确认主、备用域名的 DNS 和 HTTPS 证书可用，再启用此开关。

这是插件的可选主机名规范化功能，不会替你配置 DNS、证书、CDN 或反向代理。

## 四、主题设置页的配套整理

插件会在 Warm CY 的“设置外观”页面做界面整理，不会另造一套主题配置系统：

- 将主题原有的 10 组页面连接字段按“文字、网址、新窗口打开”组合显示；
- 将 `pinnedIds`、图片优化、缩略图优化、自定义页脚和加载模式等现有字段归入对应设置卡片；
- 对普通设置项整理标题、说明和控件布局；
- 增加进入“CY 功能显示”页面的快捷入口。

这些操作是后台页面的界面组织，不会改变这些主题字段原本的存储归属和含义。主题原有字段仍由主题设置表单保存。

## 五、与核心设置的边界

- **CSP（内容安全策略）不由 CY 插件单独管理。** 项目统一由核心安全响应头逻辑生成 CSP；默认策略已包含 YouTube、Bilibili 播放器和 Vimeo 的 frame 来源。需要额外外部域名时，使用后台“基本设置”中的 **CSP 白名单**，不要在 CY 插件里再维护一份白名单。
- 主域名来源复用核心基本设置中的 `siteUrl`，不要在插件内配置重复的主域名。
- 插件不替代主题自身的置顶字段、图片/缩略图优化、自定义页脚和加载模式设置。
- 插件不修改 Markdown 解析器的 Alert 识别规则，也不改变 Typecho 内容保存流程。

## 六、使用注意事项与排查顺序

1. 确认插件已在后台启用，且当前主题为 Warm CY；主题专属前台功能不会在其他主题下完整显示。
2. 在后台“设置 → CY 功能显示”调整插件开关并点击“保存设置”；只切换控件而未保存不会生效。
3. 置顶文章请在 Warm CY 原有主题设置中管理，确认文章已经发布；不要把页面 ID 当作文章置顶。
4. HTML 增强默认关闭。开启前确认内容发布者可信；若某段 HTML 未恢复，先检查是否属于允许的标签、属性、CSS、SVG 或 iframe 主机名范围。
5. 外部播放器被浏览器 CSP 拦截时，先检查核心“基本设置 → CSP 白名单”和浏览器控制台报错；不要通过增加 CY 插件专属 CSP 配置来处理。
6. 备用域名跳转异常时，先检查 `siteUrl`、DNS、HTTPS 证书和请求路径是否属于排除范围；需要回退时关闭“访问备用域名时自动跳转到主域名”并保存。

## 七、接口与权限概览

| 路径 | 方法 | 用途 | 权限 / 校验 |
|---|---|---|---|
| `/admin/plugin/cy-companion` | 后台页面 | CY 功能显示设置页 | 管理后台页面权限 |
| `/api/admin/cy-companion-settings` | POST | 保存插件功能开关和 Alert 样式 | 管理员身份、管理员操作校验、参数类型校验 |
| `/api/admin/theme-pin` | POST | 更新主题置顶文章列表 | 管理员身份、管理员操作校验、已发布文章校验及确认文本 |

接口不接受 GET 写入；未通过身份、方法或参数校验时会返回相应错误，不会按成功操作处理。

插件版本与主题版本独立。更新 CY 插件说明或插件本身，不代表需要修改 Warm CY 主题核心文件；本说明描述的是当前稳定版插件实际提供的功能与边界。


## 版本核对补充（2026-11-13）

- 当前 package 元数据为 1.2.0；`buildVersion` 与后台页面显示的版本标记由不同字段维护，排查版本时应分别查看，不能仅凭页面标记推断 npm 包版本。
- 备用域名跳转由 early-request provider 在常规页面处理前判断，默认关闭；只处理公开 GET/HEAD 文档请求，后台、API、安装路径、资源目录和常见静态文件排除。
- 正文 HTML 增强默认关闭。普通 Markdown 不包含 HTML 标签时会直接跳过插件私有设置读取；真正处理时仍执行片段保护、清理和恢复流程。
