# CY 服务增强插件使用说明

**插件名称：** CY 服务插件（Warm CY Companion）  
**插件 ID：** `typecho-plugin-warm-cy`  
**当前插件版本：** `1.2.0`  
**适配主题：** `typecho-theme-warm-cy`

CY 服务插件是 Warm CY 主题的配套增强插件。它不仅提供几个独立的功能开关，还对主题后台的部分设置项目进行了重新整理，并为前台增加了搜索入口、评论管理辅助、Markdown 提示框图标恢复、文章内容声明、页脚自定义内容和正文 HTML 增强等功能。

插件的设计思路是：**尽量沿用主题原有的数据和功能，不重复建立配置，不修改核心系统的内容处理规则。**

---

## 一、插件启用后会发生什么？

启用插件并使用 Warm CY 主题后，插件会自动注册配套功能。

其中一部分功能可以在后台开关，另一部分属于自动增强，不需要额外设置。

| 功能 | 是否需要手动设置 | 默认状态 |
|---|---|---|
| 评论区管理员操作按键 | 可以关闭 | 开启 |
| 全站导航搜索入口 | 可以关闭 | 开启 |
| 正文 HTML / CSS / JavaScript 增强 | 可以开启或关闭 | 关闭 |
| 备用域名自动跳转主域名 | 可以开启或关闭 | 关闭 |
| Markdown Alert 提示框图标恢复 | 自动执行 | 自动生效 |
| 后台主题设置页面整理 | 自动执行 | 自动生效 |
| 后台 CY 插件快捷入口 | 自动执行 | 自动生效 |
| 文章内容声明 | 填写内容后显示 | 留空不显示 |
| 站点底部自定义内容 | 填写内容后显示 | 留空不显示 |
| 十组页脚链接 | 按填写内容显示 | 留空不显示 |
| 首页置顶文章 | 按设置的文章 ID 显示 | 由现有设置决定 |

注意：插件必须处于启用状态，主题专属功能才会正常工作。切换到其他主题后，Warm CY 专属的前台增强和后台整理不会按原来的方式显示。

## 二、后台入口与设置页面

插件启用后，后台会增加 **CY 服务插件** 入口。

通常可以在后台“设置”菜单中找到。如果当前后台菜单布局不符合预期，插件也会尝试将入口放到主菜单中。

进入后可以看到 CY 功能管理页面。

页面中主要包含：

1. 主题原有配置项目的集中整理；
2. 评论区管理按键开关；
3. 首页搜索按键开关；
4. 正文 HTML / CSS / JavaScript 增强开关；
5. 备用域名跳转主域名开关；
6. 统一保存按钮。

修改设置后，需要点击页面底部的 **保存设置**，仅仅切换开关或修改输入框内容，并不会自动保存。

## 三、每个设置项目的详细说明

### 1. 评论区管理按键

**设置名称：** 评论区管理按键  
**默认状态：** 开启

这个选项控制管理员访问文章或独立页面时，评论区是否显示管理员操作按键。

启用后：

- 管理员登录并通过权限校验后，可以看到主题提供的评论管理操作入口；
- 插件会向主题提供当前内容类型、内容 ID、管理员地址、文章置顶状态及安全令牌等管理信息；
- 文章和独立页面均可进入相应的管理显示逻辑；
- 普通访客不会获得管理员操作信息。

关闭后：

- 前台隐藏评论区管理员操作按键；
- 不会删除评论；
- 不会改变管理员账号权限；
- 不会关闭后台原有的评论管理功能；
- 不会关闭管理接口的权限校验。

**简单理解：** 这个开关只控制前台管理员操作入口是否显示，不是评论管理权限开关。

### 2. 首页搜索按键

**设置名称：** 首页搜索按键  
**默认状态：** 开启

这个选项控制 Warm CY 主题导航区域中的搜索入口。

开启后：

- 在主题页面导航中显示搜索图标；
- 点击图标后创建并显示搜索对话框；
- 可以输入关键词进行站内搜索；
- 未输入关键词时会提示用户输入；
- 提交后跳转到站点对应的搜索地址；
- 搜索地址根据网站基本设置中的 `siteUrl` 生成，不需要在插件中重复填写域名。

插件还会处理导航区域不存在的情况，尝试将搜索入口放到其他合适位置，并监听主题的局部页面切换事件，确保新页面仍能正常显示搜索入口。

关闭后：

- 不再创建这套搜索入口；
- 不再创建对应的搜索对话框；
- 不影响 Typecho 原有搜索数据和搜索功能。

**注意：** 这是 Warm CY 主题的搜索界面增强，不是另外建立一套搜索引擎。

### 3. 正文 HTML / CSS / JavaScript 增强

**设置名称：** 正文 HTML / CSS / JavaScript 增强  
**默认状态：** 关闭

这是插件中影响范围较大的功能。

默认情况下，文章正文会按照项目原有的 Markdown 处理和 HTML 清理流程输出。开启该功能后，插件会对文章和独立页面中的部分 HTML 内容进行保护、检查和恢复，使正文能够使用更多自定义排版和交互效果。

支持范围包括：

- HTML 标签及受支持的属性；
- `class`、`id`、`data-*`、`aria-*` 等属性；
- 受规则限制的内联 `style`；
- 正文中的 `<style>` 样式块；
- 正文中的 `<script>` 脚本；
- 受限 SVG 图形；
- 允许列表中的 iframe 播放器；
- 部分音视频及其他 HTML 片段。

插件并不是简单地取消 HTML 清理，而是采用分阶段处理方式：

1. 在 Markdown 处理前保护需要保留的 HTML 片段；
2. 让正文继续经过项目原有的内容处理流程；
3. 对受保护的 HTML 进行允许列表检查和清理；
4. 在页面输出后恢复符合规则的 HTML、CSS、SVG 和 JavaScript；
5. 将 CSS 尽可能限制在文章正文范围内；
6. 按正文中脚本出现的顺序恢复和执行。

**重要兼容性提醒：**

当前设置页面明确提示：此功能与 Markdown 插件存在兼容性冲突。如果网站文章以 HTML 格式为主，可以考虑启用；如果网站主要使用 Markdown 编写文章，则不建议开启。

**重要安全提醒：**

开启后，允许通过检查的正文 JavaScript 会在访客浏览器中执行，并不是只在管理员自己的浏览器中执行。

因此：

- 只适合内容发布者可信的网站；
- 不建议开放给匿名用户或不可信投稿者；
- 不要直接粘贴来源不明的脚本；
- 如果不需要脚本交互，优先使用普通 Markdown、HTML 和 CSS；
- 多人投稿或开放投稿的网站建议保持关闭。

这个功能只处理文章和独立页面正文，不处理评论区。笔记内容由独立笔记插件处理。

### 4. 访问备用域名时自动跳转到主域名

**设置名称：** 访问备用域名时自动跳转到主域名  
**默认状态：** 关闭

适合同时使用主域名和备用域名的网站。

开启后，插件会读取网站基本设置中的 `siteUrl`，将备用域名的公开页面请求临时跳转到当前设置的主域名。

例如：

原访问地址：

`https://备用域名.com/2026/11/13/example`

跳转目标：

`https://主域名.com/2026/11/13/example`

插件会保留原来的文章路径和查询参数，不会把所有访问都简单地送到首页。

具体规则：

- 只处理公开页面的 GET 和 HEAD 请求；
- 使用 302 临时跳转；
- 保留原请求路径；
- 保留 URL 查询参数；
- 当前域名和主域名一致时不重复跳转；
- 后台、API、安装路径和主题插件资源目录排除；
- 常见图片、CSS、JS、字体、音视频、PDF、压缩文件等静态资源排除；
- 跳转响应使用 `Cache-Control: no-store`，避免浏览器或 CDN 长期缓存跳转结果。

关闭后，插件停止执行这套跳转。

**使用前注意：**

1. 先确认网站基本设置中的主站地址 `siteUrl` 正确；
2. 确认主域名和备用域名 DNS 正常；
3. 确认两个域名的 HTTPS 证书正常；
4. 再开启跳转。

这个功能不会替代 DNS、证书、CDN 或反向代理配置。

## 四、自动增强功能：不需要额外开关

这一部分是插件比较容易被忽略的功能。它们不是单独的配置选项，而是在插件启用并满足相应条件后自动运行。

### 1. Markdown Alert 提示框图标恢复

这是 CY 插件的一项自动增强。

Markdown 提示框可以用于文章中的提示、注意事项、重要说明、警告和风险提醒。

当前支持恢复五种 GitHub 风格 Markdown Alert 的图标：

| 类型 | 标识 | 用途 |
|---|---|---|
| 普通提示 | NOTE | 补充说明、信息提示 |
| 技巧建议 | TIP | 使用技巧、操作建议 |
| 重要说明 | IMPORTANT | 需要重点关注的内容 |
| 警告 | WARNING | 可能产生问题的操作 |
| 注意事项 | CAUTION | 风险和需要谨慎处理的内容 |

CY 插件会识别 Markdown 处理后生成的 Alert 结构，并在内容清理后恢复相应的 SVG 图标。

它主要解决的是提示框图标在内容处理过程中丢失、被替换或出现重复图标的问题。

**它的特点：**

- 不需要单独开启；
- 不需要填写配置；
- 自动识别五种 Alert 类型；
- 恢复对应的 SVG 图标；
- 避免原有备用图标与恢复后的 SVG 同时显示；
- 不改变 Markdown 解析器本身的 Alert 识别规则。

**目前没有以下设置：**

- 没有五种提示框的独立配色设置；
- 没有背景色编辑器；
- 没有边框颜色编辑器；
- 没有标题颜色编辑器；
- 没有图标尺寸调节选项；
- 没有提示框样式总开关。

提示框本身的解析和基础样式由 Markdown 相关处理及主题样式负责，CY 插件负责图标恢复。不要把这项功能理解成一个完整的提示框主题编辑器。

### 2. 后台设置页面自动整理

启用 CY 插件后，Warm CY 主题后台的部分设置页面会自动进行布局整理。

这项功能不需要手动开启。

主要包括：

- 增加 CY 服务插件快捷入口；
- 增加 Markdown Rehype 插件快捷入口；
- 将原本分散的十组链接配置集中整理；
- 将首页置顶文章设置整理成独立区域；
- 将图片优化设置整理成卡片；
- 将缩略图优化设置整理成卡片；
- 将站点底部自定义内容整理成卡片；
- 将页面加载模式相关设置整理到一起；
- 统一普通设置项的标题、说明和输入区域布局；
- 在主题设置页面标题区域显示主题版本标记。

这样做的目的是让主题后台更容易阅读和操作，减少原有设置项分散带来的查找成本。

**注意：** 这只是后台界面整理，不代表插件重新实现了图片优化、缩略图优化或加载模式。这些功能仍然属于主题原有设置。

### 3. 后台快捷入口自动添加

插件会尝试将 CY 服务插件入口加入后台“设置”菜单。

如果后台菜单结构发生变化，导致常规位置无法添加，插件还会尝试将入口放到后台主菜单中。

在 Warm CY 主题设置页面，也会自动显示：

- CY 服务插件入口；
- Markdown Rehype 插件入口。

这些快捷入口只是为了方便管理，不会改变两个插件各自的功能和配置归属。

### 4. 前台页面切换后的功能恢复

Warm CY 主题支持局部页面切换。

对于搜索入口和正文增强等需要在页面加载后执行的功能，插件会监听主题的页面切换事件，在新页面载入后重新检查和处理对应内容。

因此不需要每次点击站内链接后手动刷新页面，插件也会尝试确保这些前台功能继续工作。

## 五、主题原有输入选项的详细说明

CY 插件还集中整理了 Warm CY 主题的部分原有配置。

这些输入框虽然出现在 CY 服务插件页面中，但并不意味着它们都是新增加的功能。它们原本属于主题，只是现在由插件提供更集中、更方便的管理界面。

### 1. 首页置顶文章 ID

**字段名称：** `pinnedIds`

填写需要置顶的文章 ID。

例如：

`123,456,789`

多个文章 ID 可以使用英文逗号分隔。解析时会忽略无效 ID、非正整数以及重复 ID。

作用：

- 控制首页置顶文章；
- 不改变文章原来的发布时间；
- 不改变文章永久链接；
- 不会把独立页面当成文章置顶；
- 只允许已发布文章进入置顶列表。

插件还提供配套管理接口，管理员可以通过主题前台提供的管理入口对已发布文章执行置顶或取消置顶操作。

**注意：** 置顶只影响首页展示，不会让文章在其他页面自动置顶。

### 2. 十组页脚链接

主题原本提供十组链接配置，CY 插件将它们集中整理成更容易填写的形式。

每组链接由三个输入项组成。

#### （1）显示文字

字段：

- `linktxt01`
- `linktxt02`
- ...
- `linktxt10`

填写前台显示的文字。

例如：

- 关于本站
- 联系方式
- 友情链接
- 隐私政策
- 赞助支持

留空时，这组链接不显示。

#### （2）链接地址

字段：

- `links01`
- `links02`
- ...
- `links10`

填写点击文字后要打开的网址。

支持：

- `https://` 开头的网址；
- `http://` 开头的网址；
- `mailto:` 邮件地址；
- 站内链接；
- 普通域名。

例如：

`https://example.com/about`

或者：

`mailto:admin@example.com`

#### （3）在新窗口打开

字段：

- `linkblank01`
- `linkblank02`
- ...
- `linkblank10`

这是一个勾选项。

勾选后，点击对应链接时在新窗口或新标签页打开；不勾选则按普通链接方式打开。

#### 一组链接的填写示例

| 输入项 | 示例 |
|---|---|
| 显示文字 | 联系本站 |
| 链接地址 | `https://example.com/contact` |
| 在新窗口打开 | 勾选 |

十组链接相互独立，不需要全部填写。只填写实际需要显示的链接即可。

### 3. 文章内容声明

**字段名称：** `articleDeclarationHtml`

这是一个支持 HTML 的多行输入框。

填写的内容会显示在文章详情页：

- 位于文章正文末尾；
- 位于评论区之前；
- 只在文章详情页显示；
- 笔记页不显示；
- 留空则不显示。

适合放置：

- 版权声明；
- 原创说明；
- 转载说明；
- 文章更新提示；
- 内容来源；
- 免责声明；
- 作者说明；
- 文章许可协议。

支持使用 HTML 自定义排版。

#### 可用变量

| 变量 | 含义 |
|---|---|
| `{site.name}` | 网站名称 |
| `{site.url}` | 网站首页地址 |
| `{site.description}` | 网站简介 |
| `{post.title}` | 当前文章标题 |
| `{post.url}` | 当前文章完整访问地址 |

示例：

```html
<div class="article-declaration">
  <strong>版权声明</strong>
  <p>本文发布于 {site.name}。</p>
  <p>文章：{post.title}</p>
  <p>原文地址：{post.url}</p>
  <p>转载请注明出处。</p>
</div>
```

变量替换后的内容会进行 HTML 转义，避免变量中的特殊字符直接作为 HTML 结构执行。

#### 样式说明

声明区域支持自定义 HTML 和 CSS。

声明内部的 CSS 会限制在声明区块范围内，避免为了调整声明样式而直接影响整个网站。

可以根据需要设置：

- 边框；
- 背景；
- 圆角；
- 内边距；
- 标题；
- 文字颜色；
- 段落间距。

留空时，文章详情页不会显示声明区域。

### 4. 站点底部内容

**字段名称：** `footerCustomHtml`

这是一个支持 HTML 的多行输入框。

用于设置显示在站点底部的自定义内容。

可以用于：

- 网站版权信息；
- 备案信息；
- 自定义说明；
- 友情链接补充；
- 网站公告；
- 自定义 HTML 内容。

它与十组页脚链接不是同一个设置：

- 十组页脚链接负责显示一组组链接；
- 站点底部内容负责输出自定义 HTML 内容。

不需要自定义底部内容时，保持留空即可。

填写 HTML 时应确保内容来源可信，并注意不要插入不必要的脚本。

## 六、哪些设置仍然属于主题本身？

为了避免混淆，这里特别说明 CY 插件与 Warm CY 主题的配置边界。

| 配置项目 | 实际归属 | CY 插件的作用 |
|---|---|---|
| 首页置顶文章 | Warm CY 主题配置 | 提供集中管理和配套置顶接口 |
| 十组页脚链接 | Warm CY 主题配置 | 集中整理输入界面 |
| 文章内容声明 | Warm CY 主题配置 | 提供 HTML 输入和展示配套 |
| 站点底部自定义内容 | Warm CY 主题配置 | 提供更方便的编辑入口 |
| 图片优化参数 | Warm CY 主题配置 | 整理后台显示位置 |
| 缩略图优化参数 | Warm CY 主题配置 | 整理后台显示位置 |
| 页面加载模式 | Warm CY 主题配置 | 整理后台显示位置 |
| 评论管理按键 | CY 插件设置 | 控制前台显示 |
| 首页搜索按键 | CY 插件设置 | 控制前台搜索入口 |
| 正文 HTML 增强 | CY 插件设置 | 控制增强处理 |
| 备用域名跳转 | CY 插件设置 | 控制主域名跳转 |
| Markdown Alert 图标恢复 | CY 插件自动功能 | 自动恢复图标 |

这样划分可以避免同一份配置在主题和插件中重复保存，也能减少以后维护时出现设置不一致的问题。

## 七、与 Markdown 插件及核心系统的关系

### 1. 与 Markdown Rehype 插件

CY 插件和 Markdown Rehype 插件承担不同的工作。

Markdown Rehype 插件负责 Markdown 相关处理；CY 插件负责 Warm CY 配套功能以及 Alert 图标恢复。

需要特别注意：CY 的正文 HTML / CSS / JavaScript 增强开关与 Markdown 插件存在兼容性冲突。以 Markdown 为主要写作方式的网站，不建议开启正文增强。

### 2. 与核心 CSP 安全策略

CSP（内容安全策略）由项目核心统一管理。

CY 插件不会单独建立一套 CSP 配置。

如果外部播放器或资源被浏览器的 CSP 拦截，应检查后台基本设置中的 CSP 白名单，而不是在 CY 插件中寻找另一套域名白名单。

### 3. 与核心内容处理流程

CY 插件不会因为提供正文增强，就直接取消项目原有的所有 HTML 清理规则。

正文增强仍然经过插件自身的标签、属性、CSS、SVG 和 iframe 允许规则。

不符合规则的内容可能被移除或无法恢复。

## 八、使用建议

| 使用场景 | 建议 |
|---|---|
| 普通 Markdown 文章网站 | 保持正文 HTML 增强关闭 |
| 主要使用 HTML 编写文章 | 根据需要开启正文增强 |
| 多人投稿网站 | 建议保持正文增强关闭 |

| 需要文章版权声明 | 填写文章内容声明 |
| 需要自定义页脚 | 填写站点底部内容 |
| 需要首页置顶文章 | 填写文章 ID 或使用配套管理入口 |

## 九、常见问题

### 1. 为什么开启 CY 插件后就能看到提示框图标？

CY 插件内置了 Markdown Alert 图标恢复功能。开启插件后，会自动识别 Markdown 插件生成的五种 GitHub 风格提示框结构，并恢复对应的 SVG 图标：

- NOTE：提示
- TIP：建议
- IMPORTANT：重要
- WARNING：警告
- CAUTION：注意

这项功能不需要单独设置开关，也不需要额外配置图标。

**说明：** 提示框结构由 Markdown 插件生成，CY 插件负责恢复对应图标，不负责将普通引用块自动转换成提示框。

### 2. 提示框的颜色可以在 CY 页面修改吗？

目前不可以。CY 插件只负责五种 Markdown Alert 图标恢复，没有独立的提示框颜色、边框、图标尺寸设置页面。

### 3. 为什么关闭评论区管理按键后，后台仍然能管理评论？

这是正常的。该开关只控制前台管理员操作按键显示，不会修改后台权限。

### 4. 为什么搜索按钮在某些页面位置不同？

插件会根据主题当前导航结构寻找合适的位置。如果导航区域不存在，会尝试使用其他位置显示搜索入口。

### 5. 为什么正文中的 HTML 没有显示？

请检查正文增强开关是否开启、是否已经保存，以及 HTML 标签和属性是否属于当前允许范围。

如果网站主要使用 Markdown，建议不要为了单篇文章开启这项功能，以免影响 Markdown 插件的正常处理。

### 6. 文章声明为什么在首页看不到？

文章内容声明只在文章详情页显示，不在首页、笔记页或评论区显示。

### 7. 为什么备用域名没有跳转？

如果开启备用域名跳转后，访问备用域名仍然没有跳转到主域名，可以检查以下内容：

- 是否已经开启备用域名跳转；
- 修改设置后是否点击了保存；
- 基本设置中的 `siteUrl` 是否填写正确，且指向预期的主域名；
- 当前请求是否属于插件主动排除的后台、API 或静态资源路径；
- 主域名和备用域名的 DNS 解析、HTTPS 证书是否正常；
- **是否受到缓存机制影响。** 缓存插件、Cloudflare 缓存规则或其他 CDN 缓存机制，可能导致旧响应被直接返回，或者请求未按预期进入跳转处理流程，从而出现跳转失败或表现不一致的情况。

**特别提醒：** 备用域名跳转功能在实际测试中可能受到缓存配置影响。即使插件设置正确，也不能保证所有缓存环境下都能立即正常跳转。排查时建议先检查相关缓存规则，并尝试清理缓存后重新访问。

如果问题仍然存在，可以分别检查备用域名的响应状态码和响应头，确认请求是否返回了预期的 `302` 跳转响应。

### 8. 修改设置后是否需要重新部署？

普通插件设置通过后台保存到 D1，不需要因为修改一个开关就重新部署代码。

如果修改的是插件代码或版本文件，则属于另一种更新操作。

## 十、最终说明

CY 服务插件是 Warm CY 主题的配套增强组件，重点是把常用管理功能集中起来，并补足主题在前台展示、后台配置和内容扩展方面的辅助能力。

它包含可配置的功能开关，也包含无需额外配置的自动增强。

其中：

- 评论区管理按键和首页搜索入口可以按需关闭；
- 正文 HTML / CSS / JavaScript 增强默认关闭，且需要特别注意 Markdown 兼容性与脚本安全；
- 备用域名跳转默认关闭；
- Markdown Alert 图标恢复自动执行，不提供独立样式设置；
- 主题原有配置通过插件页面集中整理，但不应误认为这些主题功能都是插件重新开发的；
- 图片优化、缩略图优化和页面加载模式仍属于主题自身功能。

**本说明以当前 CY 插件 `1.2.0` 的实际实现为准。**
