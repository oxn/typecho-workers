# 补充说明：管理员登录状态与公共页面缓存隔离

## 一、修改目的

解决管理员登录访问前台时，管理员页面与普通访客页面可能共用同一份 HTML 缓存的问题。

原有缓存机制允许携带认证 Cookie 的请求参与公共页面缓存，可能产生以下情况：

1. 管理员访问前台时，生成的页面被写入公共缓存。
2. 普通访客访问时，可能读取到管理员页面缓存，出现不应显示的管理操作入口。
3. 管理员访问时，可能命中匿名访客生成的缓存，导致编辑、删除、置顶等管理入口无法正常显示。

本次修改的核心目标是：**管理员登录请求与匿名访客请求彻底隔离，不允许登录请求读写公共页面缓存。**

## 二、修改文件

文件路径：

`src/plugins/typecho-plugin-cache/cache.ts`

修改内容：

1. 引入 `hasAuthCookies` 方法。
2. 在 `requestCachePolicy()` 中增加登录 Cookie 检查。
3. 将登录状态检查放在缓存预热标记检查之前，确保登录请求无法通过预热标记进入公共缓存。

## 三、缓存隔离机制

通过 `hasAuthCookies()` 检查请求中的 Typecho 登录 Cookie：

- `__typecho_uid`
- `__typecho_authCode`

当两项 Cookie 均存在，且 UID 格式有效时，判定请求携带完整登录凭据。

此时直接返回：

`{ policy: 'bypass', reason: 'authorization' }`

这意味着：

- 不读取公共页面缓存。
- 不写入公共页面缓存。
- 不参与 L1、L2、L3 页面缓存。
- 不与匿名请求合并冷缓存渲染任务。
- 由 Astro SSR 根据当前请求的登录身份正常生成页面。

注意：这里检查的是登录 Cookie 的完整性和基本格式，并不代替数据库层面的身份验证。

## 四、不同请求的缓存规则

| 请求类型 | 缓存策略 | 说明 |
|---|---|---|
| 普通匿名访客 | 正常读写 | 可以使用公共页面缓存 |
| 携带完整登录 Cookie | 完全绕过 | 不读取、不写入公共页面缓存 |
| 携带 Authorization | 完全绕过 | 不参与公共缓存 |
| 携带预热标记的匿名请求 | 正常读写 | 可以预热公共页面 |
| 携带登录 Cookie 的预热请求 | 完全绕过 | 登录检查优先于预热标记 |
| Cache-Control: no-store | 完全绕过 | 不参与缓存 |
| Cache-Control: no-cache | 只读 | 不写入缓存 |
| 未审核评论 Cookie | 只读 | 避免评论相关页面被写入公共缓存 |

## 五、对主题管理功能的影响

本次修改与 CY 主题中的管理员操作入口配合使用。

管理员登录后访问文章或独立页面：

- 正常显示编辑入口。
- 正常显示删除入口。
- 文章页正常显示置顶入口。
- 删除、置顶等操作继续使用原有对话框及 API 逻辑。

普通访客访问相同页面：

- 不显示管理员操作入口。
- 正常使用匿名公共页面缓存。
- 不会因为管理员访问过页面而读取到管理员专属 HTML。

本次修改只调整缓存策略，不修改主题 HTML、CSS、管理 API 或文章内容渲染逻辑。

## 六、性能与资源影响

登录请求绕过公共页面缓存后，需要由 Astro SSR 正常渲染页面，因此管理员访问前台时可能比命中缓存的匿名请求多一些服务端处理开销。

但这项检查只涉及请求 Cookie 的读取和格式判断，不需要额外查询 D1、KV 或 R2，也不会增加额外的缓存读写请求。

普通匿名访客的缓存策略保持不变，不会因为增加登录状态判断而失去原有的公共缓存能力。

## 七、测试情况

本次修改后，缓存插件相关测试通过。

重点验证内容：

1. 登录请求不能写入公共页面缓存。
2. 登录请求不能读取 L1、L2 缓存。
3. 登录请求与匿名请求不能合并冷缓存渲染任务。
4. 携带登录 Cookie 的预热请求不能写入公共页面缓存。
5. 匿名请求仍然可以正常使用缓存预热机制。

完整测试套件当时仍有 8 项失败，全部集中在 `tests/unit/markdown.test.ts`，属于既有 Markdown 测试断言及 HyperDown 测试构造问题，不属于本次缓存修改范围，暂未处理。

## 八、后续维护注意事项

1. 不要将登录 Cookie 请求重新加入公共页面缓存。
2. 登录状态检查必须始终放在缓存预热标记检查之前。
3. 如果以后调整 Typecho 登录 Cookie 名称，需要同步检查 `src/lib/auth.ts` 中的 `hasAuthCookies()`。
4. 新增管理员前台功能时，应继续通过服务端登录状态和权限校验控制，不能仅依靠前端隐藏图标实现安全保护。
5. 本次修改不代表所有带有其他业务 Cookie 的请求都必须绕过缓存，后续新增 Cookie 时应根据实际隐私和缓存需求单独判断。

**最终原则：匿名请求使用公共页面缓存，登录请求独立 SSR 渲染，两种请求互不污染。**
